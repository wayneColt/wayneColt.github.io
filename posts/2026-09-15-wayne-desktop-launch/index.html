The Wayne Desktop: a keystroke that can be refused

2026-09-15 · the Wayne Desktop is live

The Wayne Desktop is live at desktop.waynecolt.com. It is a desktop surface with one unusual property: a keystroke on it does not run anything. Your device signs it, the host admits or refuses it through fourteen named doors, and an admitted intent is a decision on the record — never an effect in the world.

1 · The surface proves itself before you trust it

The host signs the manifest of the bundle it serves, as an Ed25519 closure over every file. The desktop then re-fetches each listed file with caching disabled, re-hashes it in your browser, and compares. Open the Closure window and you can watch it happen. One changed byte is REFUSED — not warned about, not quietly tolerated — and the same check runs from a command line and inside the delivery pipeline.

2 · A keystroke becomes a refusable object

Your device holds a signing key generated inside the browser, with its private half non-extractable. Clicking a control mints a signed, content-addressed, short-lived intent. The host runs it past fourteen doors in a fixed order, and every refusal names the door that refused and the question that would clear it: pair this device, reload the surface, re-mint with a shorter window, name the setting instead of the command. An executable, a path or a command line anywhere in an intent's parameters is refused by design — the surface mints, it does not run.

Pairing is an operator act. A new device shows a six-character code and waits for a person on the desk; no automated seat can approve it, and a revoked key can neither mint nor read.

3 · Skins, and what is deliberately missing

A skin repaints the entire surface and names the operating contract it carries into every intent — a reference the host records with the decision, never an executable. Three ship: the default look, a dense slate HUD for running a small business (its leading line states the number: net dollars, or hours per week), and a documented template to copy. All three are signed in the same bundle as the code, so an unsigned skin is a 404.

What is missing is stated on the surface itself, in a window built for the purpose:

  • Admitted is not applied. No accept path exists below the host. Nothing minted here has run.
  • No local agent, no system-wide hotkey, no screen reading. It is a web surface; its shortcuts work while it has focus. A local agent is specified and unbuilt — roadmap, not feature.
  • No model answers inside it. Generation intents are refused at the spend door, because this release admits no metered spend at all.

That list is the point rather than an apology for it. A surface that cannot say what it has not established is a surface whose successes you cannot check either.
